# NPC memory V4.1 — source-aware, contextual recall
Date: 2026-10-13. Production-safe read-path and semantic-write validation change.

## Purpose
The supplied NPC Life Simulation V1 concept contributes the ideas of bounded actor summary, personal goals and differentiated attention, **not** its hourly random tick, romance meters or separate in-memory database. RPG V2 already has NPC Life V4, the semantic writer and a live social-memory source. This patch improves use of those existing systems.

## Canonical data authority
- Committed TEMP RUNTIME is the current authority. The \`SOCIAL_MEMORY_CURRENT\` records retain the actual memory, \`NPC_KNOWLEDGE\` holds actor belief, \`OPEN_THREADS_CURRENT\` contains unresolved commitments, \`SYSTEM_CHAT_LOG\` holds recent messages.
- No new Google Sheet/Doc, no separate KV memory mirror, no changes to current NPC relationships, funds, save, objectives, identity or location.
- \`NPC_MEMORY_RECALL_V41\` is a **GM-only derived projection**, never a writer, friendship score, permission, emotional fact or new NPC decision.
- The permanent archive remains searchable evidence; it is never used to fabricate a current scene or automatically grant an actor unknown facts.

## Retrieval
1. Bound retrieval to the exact NPC and already loaded current records.
2. Include only active social memories with stable memory ID, Origin event, Meaning, direct Participants and explicit Who understands containing that NPC.
3. Prioritize established ANCHOR and IMPORTANT memories, then current goal, open-thread topics, known/reliably read messages and scene topic. Private boundaries/promises receive a small attention priority, not a new emotional effect.
4. Return at most 12 spotlight memories with source identifiers, explicit selection reasons and deferred count. All full authoritative original rows stay in the context for a targeted audit; no original memory is deleted, condensed or silently rewritten.
5. Topic selection does NOT force an NPC to raise the subject. GM independently decides whether it is causally relevant; the NPC may choose not to mention it.

## Recording new memories
- A new \`socialMemoryEvents UPSERT\` still requires explicit GM source-backed meaning + Origin event in the semantic commit.
- New records now **require explicit Who understands**; the writer will no longer assume every participant understood the event.
- The knowers must be a unique subset of explicitly identified participants. If source/awareness cannot be established, record a bounded thread (only if truly known and needed), or leave the event in its factual source log; NEVER manufacture an enduring NPC memory.
- RETIRE or TOUCH of already sourced records remains under the existing semantic event rules. Merely selecting a spotlight does not increment recurrence or mutate Last used.
- Earlier canonical memories are not rewritten or retroactively discredited. Rows without explicit awareness remain present in source data but are not automatically made known to a particular NPC.

## Integration and limits
- The actor behavioural frame and NPC initiative use the same awareness filter; no hidden memory can justify a new spontaneous act.
- No clock, goals, romance, employment, skills, money or player actions change as a consequence of this patch.
- Existing memory selection remains a read-only priority signal, not full semantic similarity search; a specific complicated history dispute can still require a targeted committed-log/canon lookup.
- Deno CI, regression, locked writer and save integrity checks remain release gates.
