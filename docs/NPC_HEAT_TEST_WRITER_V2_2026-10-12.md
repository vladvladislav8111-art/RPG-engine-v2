# NPC Heat receipt writer V2 — isolated TEST-only stage

**Draft, stacked on PR #57. Never activate against the real Shura save.**

## Experimental invocation gate
- Off by default: `RPG_NPC_HEAT_TEST_WRITER_ENABLED=false`.
- When enabled, `RPG_NPC_HEAT_TEST_WORKBOOK_ID` **must equal** configured `TEMP_RUNTIME_ID` and both save IDs must be in the `TEST-*` namespace.
- Source must be `ENGINE_FASTPATH`; the guard throws before any Google read or manifest write if the gate fails.
- No schema migration and no new Site/Plugin/backend. An existing isolated test workbook should have the 16-column `SESSION_LOG`.

## Writer semantics
- Receipts are generated by the engine from semantic scene, social memory and relationship events **for materialized NPC_CURRENT IDs only**.
- The caller cannot insert protected `engineNpcAttentionReceipts` or digest/epoch/integrity fields through World advances JSON.
- Successful, guarded test-only semantic prepares include receipts in the **same** `SESSION_LOG` row and append manifest.
- Version 2 uses unkeyed SHA-256 over the exact JSON bytes plus save, TX, inworld-end and scene. Legacy version 1 stays unchanged when test mode is disabled.
- Dry-run manifests are **not proof of a committed TX**. Existing legacy replay checks still need remote E2E.

## Explicitly not established
Unkeyed SHA-256 is a consistency checksum, **not an HMAC or cryptographic proof of origin**. An attacker able to modify both JSON and checksum can forge them. Two-instance remote Deno fencing, Google Sheets→Docs uncertain commit recovery and lock recovery remain unverified. Legacy rows were never backfilled. PR #57 audit is candidate-only and DOES NOT yet recognize V2 receipts as certified history; no earned Heat 2–4, promotion to KEY, automatic NPC memory pruning or additional XP may be enabled.

## Promotion gates
Prove the writer on an independently provisioned **TEST** workbook and remote Deno instances without any shared live save secrets. Then add signed/secret-keyed origin assurance and review complete-history epoch semantics; verify read-after-write and crash replay before enabling any real NPC history tiers. Separate user authorization required for merge and subsequent Production promotion.
